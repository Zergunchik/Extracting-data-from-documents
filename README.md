## 1. Что это за программа?

Это приложение для инженеров-электриков и специалистов по обслуживанию электроустановок. Оно помогает автоматически извлекать технические данные о выключателях, трансформаторах, реле и других элементах из таблиц Excel и схем в формате PDF. Вместо того чтобы вручную переписывать номиналы и типы, вы загружаете файлы – и программа формирует структурированные отчёты в Excel.

Программа предназначена для работы на Windows и запускается как обычное приложение с графическим интерфейсом. Она не требует знаний программирования – всё управление осуществляется через кнопки и галочки.

### 3.2. Вспомогательные скрипты (запускаются как отдельные процессы)

Это самостоятельные консольные утилиты, которые должны лежать в папке с программой:

- `extract_circuit_breaker.py` – извлекает силовые автоматические выключатели из Excel.
- `extract_current_transformer.py` – извлекает трансформаторы тока из Excel.
- `extract_contactors_with_relays.py` – извлекает реле и силовые контакторы из корзин.
- `extract_circuit_breaker_from_baskets.py` – извлекает вторичные автоматы из корзин (требует файл КРУС-КТС).
- `extract_secondary_circuit_breaker.py` – извлекает вторичные автоматы из PDF-спецификаций.
- `extract_relays.py` – извлекает реле (KL, K, KLB) из принципиальных схем PDF.
- `merge_circuit_breaker_QF.py` – объединяет extracted автоматы в готовый шаблон.

Они принимают аргументы командной строки:
- `--from-gui` – флаг, что запуск из GUI (влияет на формат вывода сообщений).
- `--output-dir <путь>` – папка для сохранения результата.
- `--merge` (опционально) – если нужно объединять результаты внутри скрипта (но в текущей логике объединение выполняется в `engine.py`, поэтому скрипты могут игнорировать этот флаг).
- путь к входному файлу.

Каждый скрипт должен создавать Excel‑файл в указанной папке с предсказуемым именем (см. `expected_names` в `engine.py`).

### 3.3. Взаимодействие между модулями (поток выполнения)

1. Пользователь нажимает «Запустить обработку» → `gui._запустить_обработку()` → `controller.start_processing()`.
2. `start_processing()` выполняет валидацию (наличие файлов, шаблонов, библиотеки), устанавливает флаги, блокирует кнопки, включает кнопку «Стоп» и запускает поток `_processing_thread`.
3. `_processing_thread` последовательно перебирает выбранные операции. Для каждой операции вызывает `engine.process_files_for_operation` (или `process_relays_from_pdf`), передавая:
   - `stop_check` – лямбду, проверяющую `self.stop_requested`.
   - `process_holder=self` – чтобы `engine` мог сохранить текущий дочерний процесс для последующего убийства.
4. Внутри `process_files_for_operation` для каждого входного файла:
   - Проверяется `stop_check()` – если `True`, цикл прерывается.
   - Вызывается `run_script`, который либо использует `subprocess.Popen`, либо `runpy` (в зависимости от `use_frozen`).
   - При использовании `subprocess` объект процесса сохраняется через `process_holder.set_current_process(process)`, а после завершения очищается.
   - Собираются созданные файлы и сообщения.
5. Если выбран режим `merged`, после обработки всех файлов вызывается `merge_excel_files` для объединения.
6. По окончании всех операций в `finally` блоке контроллер разблокирует интерфейс и деактивирует кнопку «Стоп».
7. При нажатии «Стоп» вызывается `controller.stop_processing()`, которая:
   - Устанавливает `stop_requested = True`.
   - Если есть активный процесс (`self.current_process`), вызывает `kill()`.
   - В следующих итерациях циклов сработает `stop_check()` и обработка прервётся.

**Важно:** Перед запуском операции «Автоматы в корзинах» GUI автоматически проверяет наличие файла КРУС-КТС (PDF с буквами "KTC" в названии) через функцию `check_ktc_file`. Если файл не найден — операция отключается с предупреждением.

### 3.4. Особенности работы в скомпилированном EXE (frozen‑режим)

- В `engine.py` флаг `use_frozen` определяет, как запускать скрипты: через `runpy` (прямой импорт модуля) или через `subprocess`.
- В режиме `frozen` невозможно использовать `subprocess` для вызова скриптов, так как они упакованы в один исполняемый файл. Поэтому используется `runpy.run_module` или `__import__`. Это ограничивает возможность принудительной остановки (нет объекта процесса для `kill()`). Поэтому в `controller.stop_processing()` проверка `self.current_process` работает только в режиме разработки (не frozen). Для полноценной поддержки остановки в EXE потребуется более сложный механизм (например, сигналы или IPC), но в текущей реализации остановка работает только для subprocess‑режима.

## 4. Как пользоваться программой

1. Убедитесь, что все нужные скрипты (`extract_*.py`, `merge_circuit_breaker_QF.py`) лежат в той же папке, что и `launcher.py`.
2. Запустите `launcher.py` (двойным щелчком или через командную строку). Если не хватает библиотек – программа предложит их установить.
3. Откроется окно:
   - Слева – настройки (режим сохранения, выбор папки для результатов).
   - Справа – основная область.
4. **Загрузите файлы**: либо перетащите их в серую область с надписью «Перетащите файлы…», либо нажмите кнопку «Загрузить файлы».
5. **Проверка файла КРУС-КТС**: если вы планируете использовать операцию «Автоматы в корзинах», убедитесь, что в папке программы есть PDF-файл с буквами "KTC" в названии (например, `...КТС...pdf`). При включении этой опции программа автоматически проверит наличие файла.
6. Выберите галочками, какие операции нужно выполнить (на вкладках `.xlsx` и `.pdf`).
7. Нажмите «Запустить обработку». Внизу появится прогресс-бар и лог сообщений.
8. Если нужно прервать – нажмите «Стоп». Программа корректно остановит текущий скрипт (в режиме разработки).
9. Готовые файлы появятся в выбранной папке результатов.

**Совет:** Для операции «Объединить автоматы в шаблон» должен присутствовать файл `Шаблон для автоматов.xlsx` в папке программы.

## 5. Как расширить или изменить проект (подробное руководство)

    - Именовать выходной файл так, чтобы его можно было найти по маске (см. `expected_names` в `engine.py`). Например, для Excel: `{stem}_Предохранители.xlsx`.

    Пример сигнатуры в конце:
    ```python
    if __name__ == "__main__":
        main()

    Шаг 2. Добавить имя скрипта в config.py

    SCRIPT_NAMES = {

    Если имя выходного файла не попадает под стандартные маски, добавьте его в словарь expected_names внутри run_script:

Для гарантированной остановки используйте в своём скрипте обработку сигналов (если это критично).

5.3. Изменение внешнего вида (цвета, шрифты, размеры)
Все настройки вынесены в config.py:

APPEARANCE_MODE – "dark" или "light".

COLOR_THEME – доступные темы customtkinter: "blue", "green", "dark-blue" и др.

Для изменения шрифтов или стилей отдельных элементов нужно править gui.py напрямую (например, аргументы font= у виджетов).

Функция process_files_for_operation в engine.py содержит блок:

if merge_mode:
    if len(all_created) > 1:
        # объединяем через merge_excel_files

        # перемещаем единственный файл

Вы можете:

Изменить суффиксы имён объединённых файлов (словарь suffix_map).

Добавить дополнительные столбцы в объединённый файл (в merge_excel_files).

Изменить название листа или формат сохранения.

5.5. Добавление новых настроек в интерфейс (например, выбор формата вывода)
В gui.py создайте новый элемент управления (например, ctk.CTkOptionMenu) и привяжите к переменной, например self.output_format_var = ctk.StringVar(value="xlsx").

В controller.py в start_processing прочитайте эту переменную через новый метод self.gui.get_output_format().

Передайте это значение в engine.py (например, добавив параметр в process_files_for_operation или в аргументы командной строки скриптов).

5.6. Добавление валидации файлов перед обработкой
В controller.start_processing (или в отдельном методе) можно реализовать проверки:

Существуют ли файлы.

Соответствуют ли они ожидаемой структуре (например, наличие нужных столбцов в Excel).

Не защищены ли PDF паролем.

Если проверка не пройдена – выводите сообщение и прерывайте запуск.

5.7. Изменение путей к скриптам или шаблонам
Всё централизовано в config.py:

TEMPLATE_FILENAME – имя файла шаблона.

LIBRARY_FILENAME – библиотека номиналов.

SCRIPT_NAMES – соответствие ключей и имён скриптов.

Меняйте эти значения, и программа будет использовать новые имена.

5.8. Локализация (русский/английский)
Все тексты интерфейса разбросаны по gui.py. Для перевода:

Найдите все строки в кавычках (кнопки, подписи, сообщения) и замените их.

Можно вынести все строки в отдельный модуль locale.py и импортировать оттуда – это упростит поддержку нескольких языков.

5.9. Добавление новых проверок в launcher.py
Если вы добавили новый пакет в зависимости, добавьте его название в список required в функции check_all_dependencies(). Также можно добавить логику установки, если пакет требует особых параметров.

6. Важные замечания для разработчиков
Не изменяйте launcher.py, если не уверены – он отвечает за установку зависимостей и точку входа.

Все скрипты-обработчики должны поддерживать аргументы --from-gui, --output-dir и (опционально) --merge. Если ваш скрипт не поддерживает GUI-режим, его нужно доработать.

При работе в режиме frozen (скомпилированный EXE) остановка через kill() недоступна, так как используется runpy. Если вам критична остановка, можно переписать логику так, чтобы даже в frozen режиме использовался subprocess с отдельным интерпретатором (но это сложнее).

При добавлении новых операций не забывайте передавать process_holder=self в вызовы process_files_for_operation и process_relays_from_pdf, иначе кнопка «Стоп» не сможет завершить процесс.

Всегда проверяйте stop_check() в циклах обработки файлов или долгих операциях, чтобы обеспечить отзывчивость интерфейса.

Используйте utils.read_process_output для декодирования вывода дочерних процессов – она корректно обрабатывает кодировки Windows.

7. Тестирование и отладка
Для проверки работы в режиме разработки запускайте python launcher.py из консоли – будут видны все сообщения об ошибках.

Для отладки конкретного скрипта запускайте его отдельно с нужными аргументами, например:
python extract_circuit_breaker.py --from-gui --output-dir ./test input.xlsx

Логи работы выводятся в область «Результаты обработки» в GUI, а также дублируются в консоль (если запускать из консоли).

При возникновении ошибок проверяйте stderr – в engine.py он сохраняется в full_output.

8. Требования к системе
Windows (7, 8, 10, 11) или Linux с графическим сервером (но интерфейс тестировался на Windows).

Установленный Python 3.8 или выше (если запускаете из исходников).

Автоматически устанавливаемые библиотеки: customtkinter, tkinterdnd2, pandas, openpyxl, pdfplumber (и их зависимости).
